# Touchline Football 1.0.0 开发与验收计划

制定于 2026-11-20，基线为市场版 0.8.3。2026-11-24 更新：0.9.0、0.9.1 与 0.9.2 的阶段验收已完成；1.0.0-rc.1 已完成真实 DSH 安装升级、至少两场直播采样和本地发布准备。射门与开球补验发现并修复了 ESPN 坐标方向和中圈传球开球识别问题，真实 DSH 复验通过，正式版未发布。0.9.x 使用固定事件序列、已有比赛样本和真实宿主完成当期回归。见[直播同步验收记录](acceptance-0.9.0.md)。

1.0.0 优先改善直播的同步和球场观感，其次改善整场回放的加载、播放和跳转。正式交付物为 DSH 插件，沿用免费数据源。下列版本号用于安排开发与验收。每完成一项，在对应复选框旁附上测试或实机记录；未遇到的真实比赛场景标为待补验。

## 0.9.0 · 直播同步

- [x] 已观察市场版 0.8.3，记录了实际轮询、比分和时钟变化。基线缺少同一事件的精确收包与显示时刻，保留缺测标记；候选版计时列入发布前直播复验。详见下方执行记录。
- [x] 根据基线处理比分与事件分批到达、重复或乱序、比分更正、半场与终场切换。断流时标明同步状态和最后更新时间。用固定事件序列复现偶发问题。
- [x] **固定输入验收。** 用相同输入比较修改前后结果。新比分可及时显示，迟到事件能与比分对齐，合法更正能生效，旧快照不会覆盖新状态；恢复连接后不会重播旧事件；终场时钟停在正确位置。记录更新耗时、样本数及异常原因。

既有[真实直播记录](acceptance-live-2026-11-17.md)覆盖比赛尾段、乌龙球和直播与回放往返。记录中的 76 秒是单次采样时的事件年龄；新的基线需要实测插件自身增加的等待时间。

## 0.9.1 · 直播球场观感

- [x] 用 0.9.0 记录的问题打磨传球、射门、进球后开球和死球。连续且可信的事件坐标可平滑衔接；坐标缺失时明确显示最后已知位置或未知状态。球员移动以事件、阵型和比赛阶段为依据，画面持续标注“事件推演”。
- [x] **验收。** 回放同一段事件输入，对比射门后球的落点、死球期间球员是否无故移动、开球时阵型是否合理，以及断流恢复的第一帧。对缺坐标、坐标突变和长时间无事件分别验证，将需在比赛中复看的动作列入发布前直播复验。

**2026-11-24 离线验收。** 使用本地 Metrica 第 1 场的 1,745 条事件，按比赛时间每 5 秒投递累计事件，在两次投递之间以 60 Hz 推演。0.9.0 与 0.9.1 使用相同输入和阵型。下表统计归一化球场坐标中的累计位移（两轴各为 0–100）。球只累计可见帧的移动，球员累计双方全部球员的移动。

| 双方球员推演移动总量 | 86,643 | 48,301 |

0.9.1 有 294 次远距离位置修正发生在球完全淡出时，旧轨迹随后清空。该对照衡量事件推演的可见运动量；尚未量化相对真实追踪轨迹的误差。18 个球场单位的衔接阈值和 0.16 秒的单程淡变时长仍需在发布前用直播复看。

固定序列覆盖近距离传球、远端射门落点、带坐标及缺坐标的犯规、缺坐标开球后的半场站位，以及断流恢复和长期无新事件。沿用“事件推演”与最近位置提示。单元测试、类型检查、候选包构建通过。官方整场追踪回放回归覆盖 58,003 帧、六次换人、跨半场及终场重播。

## 0.9.2 · 整场回放与首次体验

- [x] 缓存回放列表元数据，文件变更时更新；快速切换时取消旧下载。用十份整场规模文件记录冷启动、再次打开列表、选场到首帧的耗时和内存占用，再决定是否需要分块加载。
- [x] 在胶囊提供一键播放的自制短演示，明确标注合成数据。分别提示暂无直播、赛事源不可用、回放目录不可读及文件损坏，并给出对应操作。
- [x] **验收。** 全新配置无需命令行或本地文件即可播放、暂停和拖动演示。列表再次打开时不会重新解析未变文件，快速切换后只显示最后选择。使用[官方整场样本验收记录](acceptance-0.7.0.md)中的六个换人点，验证正反向跳转、跨半场、缺球区间和终场重播；既有 v1、v2、v3 回放均可读取。

**2026-11-24 阶段验收。** 目录内放置 Metrica 第 1 场的十份独立副本，每份 21,820,766 字节、58,003 帧。在同一台 Windows 机器上，首次请求列表耗时从全文件解析的 4,231 ms 降至 29.8 ms，再次请求为 3.0 ms。优化后首次返回时，宿主测试进程 RSS 为 42 MiB，JS 堆约 5 MiB；全文件解析时分别为 458 MiB 和 221 MiB。这是应用缓存冷启动的单次观测，操作系统文件缓存可能已预热。

通过本机回环 HTTP 和实际插件回放路由，在 Edge 测得从选择其中一场到首次完成画布绘制为 2.39 秒。选场前及首帧后的浏览器 JS 堆分别约 4.8 和 47.9 MiB。每次只下载所选场次，本版保留整文件加载；若真实 DSH 中更大文件的首帧等待或内存成为瓶颈，再评估按片段读取。

空目录配置下，一键播放内置 30 秒合成演示、暂停、跳转和重播通过浏览器回归。官方整场样本通过六处换人点正反向访问、跨半场、缺球提示及 96:40 终场重播。目录增删、损坏后替换、目录不可读和取消过时下载分别在宿主路由或客户端回归中验证。该阶段采用本机浏览器和插件宿主接口；真实 DSH 安装升级和直播验收在下一阶段执行。
