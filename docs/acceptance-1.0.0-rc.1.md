## 射门与进球后开球补验

随后继续观察大田对北京、京都对浦项两场真实直播，保存完整事件批次并核对实际画布。观测到大田场第 32 分钟、第 53 分钟的进球位置更新。记录在 18:35–19:11 存在约 36 分钟采样空档，不将这段时间计入连续观察，也不据此推算网络延迟。

检查实际事件发现此前两个功能缺口：

- ESPN 的客队射门原始终点也接近右侧球门，直接绘制时方向错误。相邻球权转换也会因为坐标基准不同而显得跨越球场。现于适配器边界将客队的起终点同时旋转到统一视角，不修改其他源或逐帧追踪文件。用本场同半场、间隔不超过 3 秒、双方转换且起终点有效的 91 对事件比较，前一终点到后一始点距离的中位数由 64.95 降至 6.60 个归一化球场单位。这衡量坐标衔接，不是球员真实轨迹误差。
- 本场多次进球后没有单独的 `kickoff` 事件，而是对方在中圈附近的第一脚传球。原来只检查事件类型，未识别这种重启。现增加保守的开球标记，球路继续使用报告的传球起终点，双方球员限速恢复各自半场站位。

修复包 SHA-256 为 `1908954e2fa3180ffe3d8ebfcf1881b69d750e8aaf5be4cc7a5b068e2dc3e7fb`，仍为本地 1.0.0-rc.1。前文 `306aa6…` 是修改前候选包，历史观测保留。通过按摘要命名的安装路径更新独立宿主和桌面，检查已安装文件匹配。独立宿主最初仍返回旧模块数据，重启后确认实际接口带有新坐标约定且客队位置已转换；桌面也通过正常退出、启动完成重载，恢复原会话后小窗和胶囊显示 72′、3–2。

### 真实 DSH 内的可重复场景

在正常签发会话中先读取实际宿主的已修正比赛详情，随后仅在独立测试页面把该真实事件序列逐段投递给已安装客户端。窗口球队简称明确加上“重放”，未变更事件坐标，不替换用户桌面的直播。这是受控的真实事件重放，不能称为自然发生的实时直播动画。

| 场景 | 结果 |
| --- | --- |
| 主队第 10 分钟射门 | 722 帧，终点约 (98.600, 53.200)，与报告终点一致，朝右侧球门。 |
| 客队第 20 分钟射偏 | 722 帧，终点约 (1.000, 58.000)，与转换后终点及一个单位绘制边界一致，朝左侧球门。 |
| 第 25 分钟进球 → 第 26 分钟中圈传球 | 722 帧，球收敛到报告的 (61.200, 58.400)，双方 22 人回到各自半场；远距离重置发生在球完全淡出时，没有画出从球门滚回中圈的虚构轨迹。 |

使用与画面对应的 rAF 时间戳核算，可见球最大速度约 24 个球场单位/秒，球员最大速度约 6 个单位/秒，均在既定限速内。最初观测脚本将上一画面对应到下一帧采样时刻，导致虚高速度；修正时间配对后保留原断言上限，复验通过。截图另行目视确认方向和站位；原始赛事、截图与采样文件不进入发布包。

42 项单元测试、类型检查、打包与固定直播浏览器回归通过。官方整场回放再次通过 58,003 帧、六次换人、缺球、跨半场、暂停恢复及终场重播；本轮首帧 1.51 秒，卡顿时钟偏差小于 1 ms。两场真实直播继续使用未替换的接口观察，受控重放单独标记。

### 修复后的自然直播衔接

京都对浦项（401912587）在未替换任何响应的观察页面中，19:30:31.837 收到第 70 分钟的进球射门事件，`shot` 与 `goal` 均为真，最初还没有报告终点，画面停在已知位置。19:31:12.464 收到对应的 1–0 比分，事件栏与小窗随后一致。19:31:42.587 开始收到第 72 分钟的中圈传球，实际宿主返回 `restart: kickoff-after-goal`。这段顺序同时覆盖事件先到、比分后到及重新开球。

开球标记对应的 7 个观察区间记录到 842 对可比较画面，最大球员单帧移动约 0.406 CSS 像素，可见球约 1.624 CSS 像素，没有新的大幅可见跳变。实际窗口截图核对到 71′、1–0 和进球事件。双方半场站位及传球终点的精确断言来自上面的受控重放，不把它写成自然直播中逐帧测得的真实球员位置。

### 本轮结论

剩余射门与进球后开球的功能验收已通过“自然直播批次观察 + 真实 DSH 中真实事件逐段重放”闭环；补验发现的方向及重新开球识别问题已经修复并复测。本地候选包目前没有已知未修复的验收阻塞项。此前的独立现场动作缺测不再作为继续等待的笼统任务，保留上游合批、缺终点和采样空档的明确限制。

修复后的 86 个源码文件和 13 个安装文件通过白名单与所查隐私模式检查；源码归档在另一空目录安装锁定依赖、执行 42 项测试并重建，包摘要与 `1908954e…` 一致。Windows 曾使用旧模块缓存，更新同版本候选包后已重启实际宿主。正式版的版本号调整、远端 CI、公开下载以及市场安装验收仍属尚未执行的发布阶段；按用户要求未发布正式版。
